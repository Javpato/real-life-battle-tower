# Offline shell and installation

After the normal Vite build, run `node scripts/build-offline.mjs`. It writes `dist/sw.js` with a content-hashed cache version and an explicit public asset allowlist. Include a manifest link to `/manifest.webmanifest` and call `registerOfflineSupport()` from `src/services/offline.ts` once during production startup. HTTPS or localhost is required. The manifest and original SVG icon make the app installable in browsers that support this manifest/icon combination; installation prompts and platform support vary.

`subscribeOfflineStatus(listener)` emits plain status objects with a user-facing message, online state, shell readiness and update availability. It returns an unsubscribe function. `getOfflineStatus()` reads the current status. An available update waits until a safe point; `applyOfflineUpdate()` must be called from a deliberate user action because it activates the update and reloads. Do not invoke it during an exercise or unsaved interaction.

The initial installation atomically precaches public HTML, JS, CSS and discovered static artwork/fonts/audio. MediaPipe model files and WebAssembly binaries are optional and cache only after a successful first request. Therefore first-ever camera use requires a connection. An optional model failure never prevents the main shell from installing. Offline navigation falls back to the built index page. The app's existing local save owns adventure and journal data; the worker does not store or transmit personal records.

Only generated allowlisted same-origin assets are cached. Supabase, Open Food Facts and other external services are never intercepted. API/auth/health/storage routes, authorization-bearing requests, query strings, non-GET requests and unknown public paths are bypassed. Dynamic navigation responses are not cached. Private/no-store responses and HTML unexpectedly returned for binary assets are not cached.

Offline mode does not provide new product lookups, remote account linking, cloud synchronization, new APK downloads, or a guarantee that the camera model has been downloaded. It does not silently queue economy or health mutations. Browser storage can be cleared or evicted; retain the app's JSON export for a separate backup. No automatic merge of divergent adventures is implied. The service worker has no background sync, push notifications, health permission changes or analytics.

Validate a production preview with browser service workers enabled: load once online, wait for readiness, switch offline and reload, explore and reopen the journal. Test model availability separately before and after its first successful download. Inspect developer tools to confirm no private/API requests appear in Cache Storage. Test an update at a safe point and verify old app caches are removed without affecting unrelated caches.
